> 沒有依據的，直接寫「本 repo 未驗證」，**不要補一個聽起來安心的答案**。`___` 是客戶要填的政策決定。
> 標 `†` 的成品在開放中的 PR 分支，不一定在你手上的版本（見 [README](README.md) 現況表）。
> 本文不是法律意見；是否可用某 AI 服務，以客戶合約與該服務當下的官方條款為準。

## 二、分級：T0–T3

| 級別 | 白話 | 例 | repo 的建議規則 |
| ---- | ---- | -- | --------------- |
| T0 公開 | 本來就公開 | 型錄、公開標準、`examples/` 合成資料 | 可上雲端或地端 |
| T1 內部 | 外洩損失有限 | SOP、去識別的範例工單與 NCR | 可上雲端（建議商業或 API 方案、先確認條款） |
| T2 機密 | 外洩傷到客戶或公司 | 圖紙、BOM、RFQ、費率、毛利、報價、客戶名 | 見下方「兩份規則不同」 |
| T3 高安規 | 合約或法規明文限制，連「有這個專案」都算 | 國防、航太、醫材等專案資料 | **不可上雲端；團隊層完全不處理**；地端須客戶與主管機關書面同意 |

**重要：repo 內兩份分級規則對 T2 不同（今天就會被問倒的點）**

- 通則（`docs/data-classification.md` †）：T2 雲端「預設不可」，須 (a) 客戶合約 / NDA 未禁止、(b) 已確認服務條款、(c) 負責人書面核准；地端可（限授權人員並留紀錄）。
- 團隊層 alpha（`team/README.zh-TW.md` †）：T2 **只能在本機 mock**，不能上聊天平台、不能給雲端模型，無豁免；T1 才會送雲端。

## 三、團隊 gateway（分身 pilot）：保證什麼、不保證什麼

alpha 實驗性，只在測試工作區與合成 / 去識別資料上試；Slack / Discord adapter 與 Claude Code driver **尚未在 CI 對真實平台測試**。不支援 LINE、Teams。

| 程式碼實際強制的 | 不保證的（要靠人與流程） |
| ---------------- | ------------------------ |
| roster 含 T3 頻道或分身，gateway 啟動即拒絕 | T3 字樣告警是**關鍵字比對，不是內容理解**；換說法、縮寫、圖號、照片內文字都擋不到，也會誤擋日常用語 |
| 含 T2 / T3 字樣的訊息不送進模型（同樣是字樣比對） | 內容去識別是否乾淨：`deid.py` 只掃通用樣式與你自己的名單 |
| 模型工具恆為唯讀（Read / Grep / Glob）；外包類能力上限為草稿 | 回答是否正確；分類標得對不對（lint 只檢查結構） |
| 核准只認按鈕點擊；身分用平台 user id，不用顯示名稱 | 日誌不含訊息文字（只存雜湊鏈）；要還原「誰問了什麼」得靠聊天平台與雲端端紀錄 |
| 稽核日誌為雜湊鏈 + 簽章檢查點；金鑰只從環境變數讀 | 驗證與簽章用同一把金鑰，**持金鑰者能偽造整條鏈**；須分離金鑰保管人與簽收人 |
| 人類每週簽收稽核檢查點（流程，非自動） | 保留期限、資料區域、零留存：取決於你與供應商的合約，repo 不替你保證 |
