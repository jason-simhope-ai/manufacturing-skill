# 服務範圍說明書（SOW）範本

> **範本，非法律文件。** 第 7–9 節（IP、資料處理、責任）務必由雙方法務審閱。
> 所有金額、天數、門檻都是 `範例` 佔位，結構可用，數字請依實際範圍自行填寫；本範本不主張任何行情。
> 甲方 = 客戶；乙方 = 顧問 / SI。階段名稱對應 [導入指南](../adoption-guide.md) 的 W0–W6。

## 1. 目的與範圍

甲方委託乙方導入 manufacturing-skill（開源，MIT）至甲方指定的 ___（部門 / 職位 / 約 N 位使用者）。
本 SOW 只含下列階段；未列者視為範圍外。導入路徑：☐ plugin 路徑　☐ 團隊層分身 pilot（需 Slack / Discord，不支援 LINE / Teams）

## 2. 各階段交付物

| 階段 | 交付物 | 備註 |
| ---- | ------ | ---- |
| W0 評估 | 探索工作坊紀錄、候選清單、N 個職位的閘門紀錄、IT 問卷答覆 | 閘門判「流程修正」的職位不進後續階段 |
| W1–W2 安裝驗證 | 安裝完成、被 Claude Code 載入、合成資料 `/quote` demo、權限設定 | 環境以雲端為預設；地端為選配、另列 |
| W3–W4 客製與資料 | `company-facts.md`（客戶自存）、私有 fork 的差異清單、去識別流程、部署檢核表 | ERP / MES 串接**不含**，見 §5 |
| W5–W6 試跑與上線 | 為期 N 週 pilot、每週指標記錄、每週稽核檢查點簽收（團隊層）、部門訓練 | 訓練 N 場 × N 分鐘 |
| 結案 | 結案報告（指標原始數字與限制）、停用 / 續行建議 | 不含「省多少錢」的承諾 |

## 3. 驗收標準（可量測）

| # | 標準 | 驗收方式 |
| - | ---- | -------- |
| A1 | 安裝成功，且 `claude plugin list` 顯示 plugin 已載入 | 現場執行並截圖。**前提**：以 `claude plugin list` 的實際輸出為準；安裝訊息顯示成功但 Claude Code 什麼都沒載入的版本不算通過 |
| A2 | `/quote` 以 `examples/` 合成資料跑出結構化報價，假設有標註 | 現場 demo；**只用合成資料** |
| A3 | N 個職位各有一份閘門紀錄（結果、理由、日期、複審日） | 書面 |
| A4 | pilot 每週記錄三項指標：人修改結論的比例、人先寫（如 D4）的比例、review 出席率，連續 N 週 | 每週記錄表；**驗收的是「有量、有如實回報」，不是數字達標** |
| A5 | 部署檢核表 A–I 區各項打勾並有負責人與日期（團隊層） | 書面 |
| A6 | 每週稽核檢查點由簽收人比對簽名（團隊層） | 簽收紀錄；金鑰保管人、簽收人皆非乙方 |

## 4. 甲方責任

指定窗口、核准人、金鑰保管人（職稱）；於約定日期提供去識別資料與環境存取；每週 15 分鐘 review；自行決定 T2 是否可送雲端並出具核准。

## 5. 排除事項

ERP / MES connector 開發（repo 僅有唯讀的 scheduler MCP 參考實作（mock data）與 ERP 介面契約）；地端模型的隔離驗證；T3 資料處理；LINE / Teams 整合；profile 內容的正確性背書；第三方服務條款解釋；硬體與 Claude 帳號 / API 費用（由甲方自付，☐ 另列）。

## 6. 假設

甲方有 Claude Code 帳號（方案：___）；流程已數位化到可匯出；有 N 位種子使用者；pilot 期間 T1 以下資料；客戶合約未禁止第三方 AI（甲方已查）。假設不成立時依 §10 變更。

## 7. 智慧財產與資料處理（請法務審閱）

- **IP**：上游 repo 維持 MIT 授權。甲方的 `company-facts`、私有 profile fork 與其內容歸 ___；乙方既有工具與方法歸乙方，授權甲方 ___。
- **repo 內只放合成資料。** 甲方資料**永不進入公開 repo**，包含 fork；`company-facts.md` 與資料夾放 repo 外，且不 `git add`。私有 profile 不得寫入真實公司名與單價。
- **資料處理**：乙方只經甲方授權處理 ___ 級資料；不在乙方設備留存甲方真實資料；結案後 N 日內刪除並書面確認；事故通報時限 ___。
- **保密**：☐ 沿用雙方既有 NDA ☐ 另訂 ___。

## 9. 保固與責任上限（請法務審閱）

驗收後 N 日內修正乙方交付物的缺陷；責任上限為 ___（常見做法是以已付費用為上限，由法務決定）；LLM 輸出可能有誤，**輸出的使用由甲方人員審核負責**，乙方不承擔輸出錯誤的間接損失。

## 10. 變更管理

任何範圍、階段、人數、資料等級、平台的變更，須書面變更單：變更內容、對交付物與費用的影響、雙方簽署後才執行；口頭追加不算。

## 11. 停止條件（對應「不過度依賴」原則）

任一成立時，雙方應暫停 pilot 並開檢討會，**不因已付費或已排程而繼續**；甲方可隨時單方暫停任何職位的分身：

1. 人修改結論的比例連續 N 週為 0（可能是照單全收），或 review 出席率連續 N 週低於 ___；
2. 核准人未閱讀即簽核，或「人先寫」的比例持續下降；
3. 指標被用於裁員、調薪、考績等人事決定；
4. T3 或未核准的 T2 內容進入分身頻道或對話；
5. 有人以「AI 做就好、不用再看」取代人工判斷；
6. 乙方與金鑰保管人、核准人、簽收人任一角色重疊。

停止後的動作：停用服務、撤銷 token 與金鑰、依 §7 處理資料、出具停用報告。
