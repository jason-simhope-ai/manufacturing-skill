# 探索工作坊（90 分鐘）

> 目的：不是賣方案，而是**判斷該不該做、做哪幾個職位、哪些資料能碰**。
> 參加者：董事長室（老闆或接班人）、各部門主管（用職稱，不記姓名）、管理部（IT / 人資）。建議 6–10 人。
> 準備：投影、白板、紙本表格（見各段）、**一台已裝好、已驗證會被載入的 plugin 的筆電**（若沒有，第 65 分鐘的 demo 改看錄影，並如實說明）。

## 議程（依分鐘）

| 分鐘 | 內容 | 做法與產出 |
| ---- | ---- | ---------- |
| 0–10 | 開場與期待對齊 | 講三句：「副駕不是替身」「判斷留在人」「今天可能的結論是不要做 AI」。請老闆當場說出他期待省什麼 |
| 10–25 | 現況盤點（W0 自評） | 對照 [導入指南](../adoption-guide.md) 的 Pre-flight 與 Red flags，逐項口頭過；流程還在紙本的先記下，不在今天硬做 |
| 25–55 | **核心練習：三分類** | 見下節。產出「候選清單」 |
| 55–70 | **閘門：真的需要 AI 嗎？** | 對候選清單逐項跑閘門。產出「閘門紀錄」 |
| 70–80 | 資料分級與「什麼不能貼」 | 用 T0–T3 把候選清單用到的資料各標一級；標 T2 / T3 的，請 IT 在場表態（接 [IT 問卷](it-data-flow-questionnaire.md)） |
| 80–87 | 示範（合成資料） | 只用 `examples/` 的合成圖紙跑 `/quote`。**不要**當場請人把真圖紙拿來試 |
| 87–90 | 收尾 | 念出結論：進 pilot / 先做流程修正 / 暫緩；指定下一步負責人與日期 |

## 核心練習：三分類（25–55 分）

每個候選能力（例：「每日排程提醒」「NCR 找相似案」「8D 排版」）放進下面三格之一。**有爭議一律歸「外包既有工作」**。

| 分類 | 判準 | 例 | 導入態度 |
| ---- | ---- | -- | -------- |
| 強化既有優勢 | 人仍親手判斷，AI 補資料與反例，讓人看得更多 | 人先寫根因，AI 找反例 | 優先 |
| 創造新能力 | 以前沒人做、也沒人因此少做事 | 每日 SPC 趨勢提醒 | 優先 |
| 外包既有工作 | 今天有人做，上線後他不再做 | 8D 報告排版、簡報資料包 | 預設不做；要做必須單獨核准、設上限、設複審日 |

對每項必問三題，**答案由「實際做事的人」說，不只問主管**：

1. 今天誰在做這件事？每週花幾小時？（要說得出數字，說不出就先量，不進閘門）
2. 上線後，那個人還親手做什麼？（若只剩「審閱／確認／核准／蓋章」，就不是強化）
3. 這個職位至少有一項「強化」或「創造」嗎？一項都沒有，這個職位不開。

## 閘門：我們需要 AI，還是需要流程修正？（55–70 分）

逐題問，**答「是」就走出口，不再往下問**：

| # | 問題 | 答案導向 |
| - | ---- | -------- |
| 1 | 根因是表單、權責、流程斷點或資料沒數位化嗎？ | 是 → **流程修正**，修完再來 |
| 2 | 偶爾用一次既有指令（`/quote`、`/inspect`）就解決嗎？ | 是 → **用既有指令**，不另外開發 |
| 3 | 痛點每週耗幾小時，說得出數字嗎？ | 否 → **暫緩**，先量 baseline |
| 4 | 在職者願意每週花 15 分鐘 review 嗎？ | 否 → **暫緩** |
| 5 | 需要的資料已數位化、可匯出嗎？ | 否 → **暫緩** |
| 6 | 涉及高安規客製專案（T3）嗎？ | **只在紙上自行填 yes / no，不要說出專案、不要輸入任何聊天或 AI**；yes → 本專案不處理 |

結果只有四種：`進 pilot`、`流程修正`、`用既有指令`、`暫緩`。把結果與一句理由寫進「閘門紀錄」（欄位見交付物清單）。
`team/gate/need-a-twin.md`（若你手上的版本有）是這張表的完整版（G1–G7），團隊層 pilot 以它為準。

## 各部門主管的提問（通用職稱）

| 對象 | 問題 |
| ---- | ---- |
| 董事長室 | 你期待省什麼？如果結果是「流程要先改」，你接受嗎？誰有權說「暫停」？指標若顯示 AI 被人照單全收，你要停嗎？ |
| 生產部主管 | 早會現在怎麼開？排程資料誰整理、存在哪？最常被插單打亂的是哪一段？ |
| 品保部主管 | 最近三件 NCR / 客訴怎麼處理？根因誰先寫？客戶規範（CSR）有沒有限制第三方 AI？ |
| 技術部主管 | 工程變更（ECN）流程在哪斷？BOM where-used 查得到嗎？ |
| 業務部主管 | 一份報價從 RFQ 到送出平均幾小時？報價單與費率放哪？價格敏感資料誰能看？ |
| 加工部主管 | 現場資料有沒有數位化？換線與試切紀錄怎麼留？ |
| 管理部主管（IT / 人資） | 現有帳號與權限怎麼管？能不能接受 T1 內容送雲端模型？有沒有影子 AI（員工自用個人帳號）？ |

## 工作坊產出

1. **候選清單**：每列 = 能力、今天誰做、每週小時、人仍親手做什麼、三分類、資料最高等級。
2. **閘門紀錄**：每個職位一份（結果、理由、日期、複審日）。
3. **風險與限制清單**：IT 當場提出、尚未能回答的問題（原樣記下，帶回問卷）。
4. **下一步**：誰、何時、做什麼；進 pilot 的才附 [pilot 一頁紙](pilot-one-pager.md) 與 [SOW](sow-template.md)。

## 不要承諾的事（會後客戶會拿來對照）

- 「資料不出公司」「完全 air-gap」「不外流圖紙」：預設是雲端模型，附檔就是送出；地端是選配且**本專案未端到端驗證**。
- 「保證不裁員」或「保證能省人」：兩者都不要保證。只能說本專案的設計目標是副駕不是替身、指標不用於人事決定，並請客戶自己把原則寫成文件。
- 「100% 準確」「3 個月回本」「跨產業萬能」「現成接你的 ERP」。
- 任何沒有在 repo 內的功能（先確認檔案存在；PR 中的成品請說「規劃中」）。
- 在工作坊中收下真圖紙、報價單、客戶名單。收到就是你的資料處理責任（見 SOW 第 7 節）。
