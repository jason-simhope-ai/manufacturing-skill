### 2.2 Key decisions

- **CI scope is intentionally minimal**: lint + JSON validate. We do not attempt to actually invoke Claude / install the plugin in CI — that would require API keys, brittle browser automation, and would generate false positives. The CI's job is "this repo is well-formed."
- **All files in English**: contributor-facing, international-developer audience.
- **CHANGELOG follows SemVer + Keep-a-Changelog conventions**, matching the version field in `plugin.json` (currently 0.1.0 → bump to 0.1.1).
- **Issue templates use GitHub's modern `.yml` form syntax**, not the legacy markdown templates.

- CI workflow runs on first PR / push and goes green.
- README is unchanged for this part (it already links to LICENSE / docs / etc.; CONTRIBUTING gets surfaced via GitHub's auto-display).

### 3.3 Honesty constraints (hard rules for the content)

- Every agent / skill / know-how file MUST include a frontmatter or top-of-body note: _"This profile is alpha — content authored from public industry references, not validated by an active injection-molding practitioner. Pull requests welcome."_
- The `polymer-material-database.md` MUST include a header note: _"Values are typical ranges from generic literature. For production use, ALWAYS consult the actual supplier datasheet for the specific grade you procure."_
- No claim that this profile is production-ready, IATF-validated, or replaces a process engineer.

## 6. Risks and mitigations

| Risk                                                                                   | Mitigation                                                                                                                                      |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| CI workflow uses a tool not installed in default GitHub runner                         | Stick to `npx markdownlint-cli2` + `python -m json.tool` only — both pre-installed                                                              |
| Issue templates' YAML form syntax breaks GitHub form rendering                         | Use simple field types (input, textarea, dropdown, checkboxes) — no advanced features                                                           |
| Injection-molding content has factual errors a practitioner would spot                 | Honest "alpha, needs validation" labels everywhere; explicit invitation to PR corrections                                                       |
| `plugin.json` schema change (adding `profiles.alpha`) breaks existing install.sh logic | install.sh only reads `profiles.<name>` directories, doesn't parse the array structure beyond the `complete`/`stub` list — verify before commit |
