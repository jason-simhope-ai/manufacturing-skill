## 1. Goals

After v0.1.1 ship-and-review, three polish gaps and three capability gaps were identified. v0.1.2 closes all six in a single release.

### 1.1 Polish (from v0.1.1 review)

- **P1** — CI frontmatter check uses naive string-grep, not real YAML parse. Edge cases could give false negatives.
- **P2** — No `.github/ISSUE_TEMPLATE/config.yml`. Users with questions / commercial inquiries get routed into bug-report by default.
- **P3** — README has no CI badge. Looks like a personal toy from the outside.

### 1.2 Capability bundles

- **A — Knowledge depth**: three reference docs that core agents repeatedly need: GD&T, FMEA/PFMEA, INCOTERMS.
- **B — Daily high-frequency commands**: two commands plant managers and quality engineers use every day: `/morning-briefing`, `/8d`. Plus a skill backing the latter.
- **C — Engineering Change Management**: one of the largest capability holes — no factory operates without ECN/ECO. Add 1 agent + 1 skill + 1 know-how.

## 4. Order of work

To keep commits coherent and reviewable:

1. **Spec doc commit** (this file)
2. **Polish commit** — P1 + P2 + P3 in one commit (`chore`)
3. **Bundle A commit** — 3 know-how files (`feat(know-how)`)
4. **Bundle B commit** — 2 commands + 1 skill (`feat(commands)`)
5. **Bundle C commit** — 1 agent + 1 skill + 1 know-how (`feat(ecm)`)
6. **Manifest commit** — CHANGELOG + plugin.json + INVENTORY + explainer counts (`chore(release)`)
7. Push after each commit; CI verifies invariants automatically.

Doing it as 6 separate commits (instead of one giant commit) so:

- If any one bundle has an issue you can revert / iterate just that part
- The git log reads as a coherent v0.1.2 progression
- Each push triggers CI; if a bundle breaks something we catch it before doing the next

## 5. Honesty constraints

- **GD&T** content cites ASME Y14.5; explicit note that drawings using ISO 1101 differ slightly in symbol convention.
- **FMEA** content uses AIAG-VDA harmonized method (the post-2019 unified version), not the legacy AIAG-only or VDA-only methods. Header notes this.
- **INCOTERMS** content uses **INCOTERMS 2020**; explicit note that older contracts may reference 2010 (DAT replaced by DPU is the famous change).
- **8D** content notes Ford's original definition (the canonical source) and that some modern teams add D9 (transfer to other product lines) — we cover D1-D8 only.
- **`engineering-change-manager` agent** does not assume any specific PLM tool — instead it works against generic ECN/ECO concepts and dispatches to existing core agents (production-planner / quality-inspector / inventory-manager) for operational impact.

## 6. Out of scope (deferred)

- `gd-and-t` symbol image embedding — text-only for now (markdown limitations; images would need to be SVG add-ons)
- FMEA software interface (e.g. APIS IQ-FMEA, Plato Scio) — this is a methodology doc only
- ECM integration with PLM systems (PTC Windchill / Teamcenter) — future v0.2 if a real adopter needs it
- Tagged release v0.1.2 — done after this commit lands and CI is green
- Translation of CHANGELOG / SECURITY / CONTRIBUTING into 繁中 — international-first per the language convention table

## 7. Risks

| Risk                                                                                                        | Mitigation                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `pyyaml` install adds CI time                                                                               | `pip install pyyaml` is sub-second on GitHub runners — negligible                                                            |
| New `config.yml` syntax breaks the GitHub issue picker UI                                                   | YAML is well-documented; copy from GitHub's own docs                                                                         |
| GD&T content has factual errors a metrology engineer would spot                                             | Stick to the universally-agreed Y14.5 symbol list; flag as "reference, see ASME Y14.5 for definitive interpretation"         |
| `/morning-briefing` claims to pull live data but the scheduler-mcp / erp-connector aren't fully implemented | Command doc explains it works against mock data when MCP isn't connected, and what fields are needed for real implementation |
| ECM agent overlaps with quote-specialist on price-impact analysis                                           | Clearly delineate: ECM owns the change process; quote-specialist is dispatched only for price re-quote                       |
