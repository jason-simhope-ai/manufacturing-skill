# 資料分級與 AI 工具使用規則

> 給導入負責人與資安 / IT 看的一頁版。分級是**建議起點**，請依貴公司客戶合約、NDA 與法規調整，並由負責人簽核。
> 本文件不是法律意見；是否可使用某 AI 服務，以客戶合約與該服務當下的官方條款為準。

---

## 四個等級

| 等級 | 名稱 | 說明 | 機械加工 / 壓鑄 / 射出廠的例子 |
| ---- | ---- | ---- | ------------------------------ |
| T0 | 公開 | 外洩無影響 | 公司官網內容、公開型錄、公開的材料規格與標準、本 repo 的 `examples/` 合成資料 |
| T1 | 內部 | 不對外，外洩造成輕微困擾 | 內部 SOP、作業流程文件、去識別化的範例工單、通用品質教材、不含客戶資訊的製程說明 |
| T2 | 機密 | 外洩造成商業或合約損失 | 客戶圖紙與 BOM、RFQ 內容、機台費率、毛利與報價單、客戶名單與價格、模具設計、製程參數、良率與客訴紀錄 |
| T3 | 高安規限制 | 受合約或法規明文限制 | 高安規客製專案（例：國防、航太、醫療器材客戶）的受控技術資料、圖紙與規格、客戶明令不得交第三方的資料 |

> 判斷原則：**拿不準就往上一級**。同一份文件含多種內容時，以最高等級者為準。

## 可去哪裡：規則表

| 等級 | 雲端模型（商業 / API 條款） | 地端模型（自家機房） | 完全不使用 AI 工具 |
| ---- | --------------------------- | -------------------- | ------------------ |
| T0 | 可 | 可 | — |
| T1 | 可（建議使用商業或 API 方案，並確認條款） | 可 | — |
| T2 | 預設不可；須 (a) 客戶合約 / NDA 未禁止、(b) 已確認服務條款、(c) 負責人書面核准 | 可（限已授權人員，並保留使用紀錄） | 客戶合約禁止者 |
| T3 | **不可** | 僅在客戶與主管機關書面同意、隔離方案經驗證後才可 | **預設**：未取得書面同意前一律不使用 |

幾點補充：

1. 「地端」不等於自動合規。是否可用，仍取決於客戶合約與機房 / 網路隔離方式。
2. 把檔案以 `@檔案` 附到 Claude Code，等同於把該檔案內容送到所選模型服務；請當成「貼進去」處理。
3. 去識別化（拿掉客戶名、料號、尺寸）可降低等級，但須由負責人確認已無法回推。

## 個人方案與商業 / API 方案的資料條款

不同方案（個人訂閱、團隊或企業方案、API）對資料如何保存、是否用於改進模型、可否簽署資料處理協議，**各家服務與各個時期的條款不同**。
本 repo 不為任何條款做保證；**以你實際使用的方案、當下版本的官方條款為準**，並在導入前把確認日期記進
`company-facts.md`。尤其不要用個人方案處理 T2 以上的資料。

## 使用前檢查清單

- [ ] 這份資料是 T0–T3 哪一級？（拿不準就往上）
- [ ] 客戶合約 / NDA / CSR 對第三方 AI 服務有沒有限制？
- [ ] 我用的是哪種帳號與方案？條款確認過了嗎？
- [ ] 需要核准嗎？核准人是誰？（見 `company-facts.md` 的核准表）
- [ ] 真實資料是否放在 repo 之外，且沒有被 `git add`？
