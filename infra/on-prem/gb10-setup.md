# 地端 LLM 安裝指南：GB10 + Ollama

> 給 IT 部門的硬體規格 + 軟體部署指南。
> 目標：讓模型在自家伺服器跑，降低圖紙與資料送往雲端的機會。

> ⚠️ **未經本專案驗證（請先讀完再決定要不要照做）**
>
> - 本專案**預設使用 Anthropic 雲端模型（Claude Code）**，地端只是選配方案。
> - 本文件的硬體與 Ollama 安裝步驟是通用做法；**「讓 Claude Code 改用 Ollama」「air-gap（完全隔離外網）」這兩件事，本專案沒有在真機上端到端驗證過**，不能當作「資料已不出公司」的保證，也不要拿去對客戶或稽核員做這樣的聲明。
> - 在你自己完成下方「[自行驗證隔離](#自行驗證隔離)」之前，請一律假設：你輸入或附上的內容仍可能被送到雲端。

---

## 為什麼要地端

| 雲端 LLM               | 地端 LLM                                  |
| ---------------------- | ----------------------------------------- |
| 資料要傳出去           | 資料留在內網（**需自行驗證**，見下方）    |
| 客戶稽核可能擋         | 較容易回應稽核，但仍須提出自己的驗證證據  |
| 月費（每 token 計）    | 一次硬體投資、長期免費                    |
| 模型強（GPT-4 / Opus） | 模型中等（Qwen 2.5 / Llama 3 / DeepSeek） |
| 網路斷就掛             | 工廠停網仍可用                            |

對有保密要求的 OEM 客戶：地端值得評估，但是否採用、能否被接受，由客戶合約與你公司自己的資安政策決定，不是本專案說了算。

## 軟體部署（GB10）

### 1. 系統初始化

```bash
# 接電源、接網路、接螢幕
# 開機跑 DGX OS 初始設定（一次）
sudo apt update && sudo apt upgrade -y
```

### 2. 安裝 Ollama

```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable ollama
sudo systemctl start ollama
```

> `curl ... | sh` 是直接執行網路上的腳本；正式環境建議先下載、檢視內容或改用你公司核可的安裝管道。

### 3. 下載推薦模型

> 注意：部分受管制或有採購限制的客戶（國防、政府、特定國家供應鏈規範）可能對模型的**來源國或授權**有限制，下列 Qwen / DeepSeek 等模型不一定適用；能不能用，由客戶自己的政策決定，請先與客戶確認。

```bash
# 一般用途（回應快）
ollama pull qwen2.5:14b

# 較強（回應慢但答得好）
ollama pull qwen2.5:32b
ollama pull deepseek-coder:33b

# 高階（GB10 最大可跑）
ollama pull qwen2.5:72b
```

### 4. 驗證跑得起來

```bash
ollama run qwen2.5:14b
>>> 報價的 6 個基本步驟是什麼？
```

### 5. 讓 Claude Code 改用地端模型（**未經本專案驗證**）

> ⛔ **未經本專案驗證。** 下面描述的是「想達成的設定意圖」，**不是可直接貼上的設定檔**。
>
> 本專案**無法確認** Claude Code 的 `~/.claude/settings.json` 是否認得 `llm.primary` / `llm.fallback` 這類設定鍵。如果這些鍵不存在，Claude Code 會直接忽略它們，而你會以為已經切到地端、實際上仍連 Anthropic 雲端 — 這是最危險的情況。
>
> 請**不要**依賴任何「貼一段 JSON 就隔離」的做法。實際可用的設定方式，請以 Claude Code 官方文件與你自己的測試為準，並用下方的驗證步驟證明。

設定意圖（僅供規劃，不是設定檔內容）：

- 平常（`primary`）：Anthropic 雲端的 Claude。
- 備援（`fallback`）：Ollama，端點 `http://localhost:11434`，模型 `qwen2.5:32b`。
- 注意 `fallback` 的語意是「雲端不可用時才改走地端」，**不等於**「不連雲端」。
- 注意 `localhost` 只有 GB10 本機自己連得到；若工程師電腦要透過內網連 GB10，端點要改成內網位址，並依下方資安清單限制 Ollama 的監聽範圍。
- 離線（air-gap）環境無法 `ollama pull`，模型檔要在可上網的機器下載、檢查雜湊值後，以內部管道搬進來；本專案未寫出完整搬運流程。
- Claude Code 本身的登入、遙測、自動更新等連線，是否可關閉、怎麼關，也需要另外查證與處理。

## 網路架構

```
工廠網路
  ├─ ERP / MES (內網)
  ├─ GB10 (內網, 192.168.X.X) ← Ollama
  ├─ 工程師電腦 (內網) ← Claude Code
  └─ 防火牆
       └─ 外網 (Anthropic API 線上時用)

最敏感場景（想避免圖紙送出）— 以下為規劃方向，未經本專案驗證：
  - 讓 Claude Code 改走 ollama（設定方式見上方「未經驗證」說明）
  - 防火牆封鎖 Claude Code 相關對外流量（含 anthropic.com）
  - 最終是否真的零外送，要用下方方法實測
```

### 自行驗證隔離

不要用「我已經改設定了」當證據。請 IT 自己照下面步驟做，並留下紀錄（截圖、log）：

1. **出口防火牆規則（egress deny）：** 在工程師電腦與 GB10 所在網段的對外出口，預設拒絕所有對外連線，只放行明確需要的目的地（例如內網 ERP）。封鎖規則要涵蓋 `anthropic.com`、`claude.ai` 及其子網域，以及 DNS 解析結果對應的 IP；注意不要只封一個網域名稱而漏掉別的連線。
2. **觀察實際對外流量：** 在防火牆 log，或在工程師電腦用封包工具（例如 `tcpdump`、Wireshark、`ss -tnp`），一邊用**假圖紙**跑一次完整的 `/quote`，一邊確認**沒有任何**連往雲端的連線，也沒有被防火牆擋下的嘗試紀錄（被擋下代表它還想連出去，設定其實沒切乾淨）。
3. **做對照組：** 暫時開放出口再跑一次，確認你的觀察方法真的看得到流量；否則「沒看到流量」可能只是看錯地方。
4. 通過後再用真實資料；每次升級 Claude Code、Ollama 或模型之後，重做一次。

## 資安檢查清單（給 IT 稽核用）

- [ ] GB10 在工廠內網，無公網 IP
- [ ] Ollama 只 listen on localhost (`OLLAMA_HOST=127.0.0.1:11434`) 或內網段
- [ ] 已依上方「自行驗證隔離」完成出口封鎖與流量觀察，並留存紀錄
- [ ] 模型權重落在加密 SSD（DGX OS 預設啟用 LUKS）
- [ ] AI 生成的所有 record 寫入 audit log
- [ ] 圖紙、BOM 等敏感檔案 `.gitignore` 確實排除
- [ ] 定期備份：權重、自訂 fine-tune（如有）
- [ ] 漏洞管理：Ollama / 模型版本定期更新
- [ ] 物理安全：GB10 放上鎖機櫃 / 有監視

## Troubleshooting

| 症狀                      | 原因                     | 解法                                        |
| ------------------------- | ------------------------ | ------------------------------------------- |
| Ollama 跑超慢             | 模型超過 unified memory  | 降模型大小（72b → 32b）                     |
| Claude Code 連不到 Ollama | endpoint 設錯，或 Claude Code 本身不支援此接法（未經本專案驗證） | 先確認 `http://localhost:11434/api/tags` 能回；再查 Claude Code 官方文件 |
| 模型答非所問              | 模型太小 / prompt 太複雜 | 升模型 / 簡化 prompt                        |
| 機台溫度爆                | 散熱不良                 | 確保進出風口暢通、室溫 < 28°C               |

| 項目                                  | 月成本            |
| ------------------------------------- | ----------------- |
| 電費（200W × 24h × 30d × NT$3.5/kWh） | ~ NT$500          |

| 維護（年保險）                        | ~ NT$500/月       |
