## [Unreleased]

**Digital-twin team (v0.2.0-alpha, experimental).** A seventh layer (TEAM) and a third tier (`team/`) that give each position a copilot "twin" in chat — a copilot, not a replacement. Alpha stops at `observe / suggest / draft`: there are no write tools, no long-term memory, and T3 (high-assurance custom projects) is always refused. Design: [spec](docs/superpowers/specs/2026-10-05-digital-twin-team-design.md).

  - **Review fixes (PR #38 adversarial review P-01–P-09, IT day-one dry run I04–I06)**:
    - **Data-root scan fails closed** (P-01) — files the scan cannot read (PDF, Office/ZIP, OLE, images and other binaries, UTF-16 without a BOM, mostly undecodable bytes, files over 2 MB) now refuse start (exit 3) and calls (`policy_denied` / `data_root:unscanned`) unless `MFG_TEAM_DATA_ALLOW_UNSCANNED=1` (documented risk: the model then reads unchecked content). UTF-16/32 with a BOM is decoded and scanned; UTF-8 with stray bytes is scanned with them replaced (and as cp950 when that also decodes). Scan cache version 2 forces a rescan.
    - **Special files** (P-06) — a FIFO, socket or device in the data root is refused (`data_root:special_file`) from `lstat`, never opened; regular files are opened `O_NOFOLLOW | O_NONBLOCK` and re-checked with `fstat`, so a swap after `lstat` is caught.
    - **Secret shapes in data files** (P-07) — new `DATA_SECRET_PATTERNS` (all `SECRET_PATTERNS` plus any PEM/PGP private-key header, `AKIA…`, `xoxb-`/`xoxp-`, `sk-ant-`, `ghp_`, `api_key = <value>`); a hit counts as T3.
    - **Freeze is enforced end to end** (P-03, P-04) — the flag is re-checked after the model returns, before every post in `run()` and right before an approved action executes (`ApprovalBook.resolve(may_execute=)`); a reply in flight is dropped (audit `frozen` / `frozen_in_flight`). A freeze voids every pending approval card (`approval_expired` / `frozen`), including a freeze that began and ended between two events (`unfreeze` now renames the flag to `frozen.last`, whose mtime marks the freeze); no new cards while frozen; a click during the freeze gets 「分身暫停服務中」 (rate-limited like messages) and a click on a voided card after unfreeze gets 「核准卡已因凍結失效」.
    - **`freeze` / `unfreeze` never create the state dir** (P-05) — they require it to exist with the expected owner and mode and to hold `audit/`, else exit 78 naming the path.
    - **Anchor replay** (P-09) — `audit-verify --anchor` also fails when a validly signed heads file in the anchor's or `--heads-out`'s directory has a higher seq (a rolled-back `latest.json`).
    - **Denylist required on real platforms** (I05) — a non-mock adapter without a denylist, or with an empty one, refuses start (exit 64) unless `MFG_TEAM_NO_DENYLIST=1`; `self-check` prints the path and entry count; `config_loaded` records them in `driver_info.denylist`.
    - **Freeze and the persisted daily budget together** — the freeze flag is checked before the daily-budget check, so a frozen gateway answers 「分身暫停服務中」, not the budget notice; a reply dropped because the flag appeared while the model ran is still charged to `daily-spend.json` (the cost was incurred). `self-check` prints the daily budget next to the denylist. `teamctl state-reset` accepts a state dir holding `frozen`, `frozen.last`, `data-scan.json` (+ `.tmp`) and `daily-spend.json` (+ `.tmp`, `.lock`). Spec revision v2.5 records the review fixes (v2.4 is the owner round).
    - **Key mismatch is not reported as tampering** (I04) — when nothing in the audit chain verifies under the configured key (e.g. a mock rehearsal with the demo key in the production state dir), the exit-78 message says the chain was started under the demo key or another key and to archive it and start a new chain; a genuine mismatch under one key keeps the tamper wording. `self-check` warns when demo keys wrote to the state dir and notes an existing chain.
    - **Weekly audit is runnable as written** (I06) — `audit-verify` prints the deny counts summed over all tier files; new `infra/chat-gateway/audit-weekly.sh` for a systemd timer (service user, same `EnvironmentFile`; refuses without `latest.json`; pushes off-host before advancing `latest.json`).
