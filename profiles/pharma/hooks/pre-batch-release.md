# pre-batch-release Hook（製藥 / 醫材）

> ⚠️ **Alpha**：此 hook 只檢查「放行要件的文件是否齊備」，**不做放行判定**。批次放行由 QA / QP（或依法規與公司授權的品質單位放行人員）簽核。AI 產出不是 GMP 紀錄。
>
> 用獨立名稱而非覆寫 core [`pre-ship`](../../../core/hooks/pre-ship.md)：GMP 產品要**先**通過品質放行，之後出貨時仍照常跑 core `pre-ship`。

藥品與醫材一旦放行出廠，出問題就是回收與通報。這關問的是「放行包齊不齊」，不是「產品好不好」。

---

## 檢查清單

### A. 品質放行要件

- [ ] **批次紀錄已完成 QA 審查**並簽署（製造 + 包裝；醫材為 DHR）— AI 預檢清單不算（見 [`batch-record-reviewer`](../agents/batch-record-reviewer.md)）
- [ ] **成品檢驗 / CoA** 已出具並經 QC 核准；委外檢驗報告已回
- [ ] 本批相關**偏差全部已結案**，或 QA 已書面評估「未結案偏差對本批無影響」並依程序核准（依公司程序書）
- [ ] 本批相關 **OOS / OOT 調查**已結案
- [ ] 本批涉及的**變更管制**已核准，且實施前條件（再確認、法規核准）已完成
- [ ] 設備、製程、清潔、電腦化系統的**確效 / 確認狀態**在本批生產期間有效
- [ ] 原料 / 包材皆為**已放行**狀態，供應商資格有效
- [ ] 符合**上市許可 / 註冊內容**（配方、製程、規格、標籤）— 有疑義轉法規事務
- [ ] 環境監測（無菌製劑）、留樣、穩定性計畫登錄（如適用）已完成
- [ ] **QA / QP 放行簽核**欄位存在且尚待簽署人親簽（AI 不代簽、不預填）

### B. 出貨要件

QA 放行後，照 core [`pre-ship`](../../../core/hooks/pre-ship.md) 檢查包裝、標籤、隨貨文件（CoA 依客戶要求）、運送溫度條件（如冷鏈）。

> 非 GMP 料號（多 profile 安裝時）略過 A 段，直接走 core `pre-ship`。

---

## 失敗處理

任一項缺：

```
🛑 放行文件未齊 — AI-DRAFT 檢查結果（非 GMP 紀錄）
- 批號 <批號>：偏差 DEV-<編號> 狀態「調查中」，未見 QA 影響評估
- CoA：含量結果已出，微生物限量報告未回

這是文件齊備檢查，不是放行判定，也不是產品品質判定。
補齊後由 QA / QP 審查並簽核，再重新觸發 pre-batch-release。
```

---

## 通過動作

- 輸出「放行文件包齊備摘要」，**等待 QA / QP 審查與簽核**（AI 不代簽）
- 放行簽核後：由權責人員在受控系統更新批次狀態 → 進入出貨流程（core `pre-ship`）
- 放行紀錄本身由 QA 在受控系統產出，**不是**這份 AI 摘要
