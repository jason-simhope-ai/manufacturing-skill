# 批次追溯與回收演練 Skill

> ⚠️ **Alpha**：演練方法依 ISO 22000 與 GFSI 系標準常見要求整理。**演練目標時間、質量平衡容許差、台灣回收分級與通報時限均為範例或需驗證**，請以你適用的驗證標準與衛福部食藥署現行規定為準。

由 **traceability-officer** 主導，**haccp-coordinator** 會引用。

---

## 一步向前、一步向後

```
供應商 ──▶ 原料進貨批 ──▶ 生產批（投料、重工、混批）──▶ 成品批 ──▶ 客戶 / 通路
        ◀── 向後追（trace back）        向前追（trace forward）──▶
```

每一個箭頭都要有**紀錄 + 批號 + 數量**：

| 環節     | 必要紀錄                         | 常見斷點                         |
| -------- | -------------------------------- | -------------------------------- |
| 原料進貨 | 驗收單、供應商批號、自編進貨批號 | 散裝原料分桶後沒標批號           |
| 投料     | 領料單 / 投料紀錄（批號 + 重量） | 「同上」、只寫品名不寫批號       |
| 重工     | 重工來源批號、投入哪個新批       | 重工品混入新批沒登錄             |
| 包裝     | 包材批號、印字批號 / 有效日期    | 換包材捲沒記錄                   |
| 出貨     | 出貨單含成品批號與數量           | 出貨單只有品名                   |

## 回收演練 6 步驟

### 1. 出題（由非執行者出題）

隨機選一個條件，例如：「供應商通知：原料 A 進貨批 <批號> 可能含未標示過敏原」或「客訴：成品批 <批號> 有金屬異物」。記下**開始時間**。

### 2. 向後追

找出起始批涉及的所有原料批、包材批、產線、班別、CCP 紀錄。

### 3. 向前追

找出所有受影響成品批 → 出貨客戶、數量、日期 → 尚在庫存數量。

### 4. 質量平衡

```
質量平衡 % = (已出貨 + 庫存 + 報廢 / 損耗 + 留樣) ÷ 生產（或投入）量 × 100%
```

| 結果               | 意義（範例判讀，容許差需依你的標準設定） |
| ------------------ | ---------------------------------------- |
| ≈ 100%（例 ±2%） | 帳物相符                                 |
| 明顯 < 100%        | 有出貨或損耗沒登錄 → 斷點                |
| 明顯 > 100%        | 有混批 / 重工投入沒登錄 → 斷點           |

### 5. 停錶 + 模擬通知

記下**結束時間**。起草「若真實發生」的客戶通知草稿與內部通報流程（**不實際發送**）。常見稽核期待是在數小時內完成追溯（例：4 小時 — 範例，需驗證你的標準要求）。

### 6. 檢討

列出斷點、超時原因、改善事項（負責人 + 期限），歸檔為演練紀錄。

## Output 範例

```
回收演練紀錄 — <日期>　出題人：<姓名>　執行人：<姓名>
情境：原料 A 進貨批 <批號> 疑似未標示過敏原
耗時：2 小時 35 分（目標 4 小時 — 範例）
影響成品批：3 批，生產 1,200 箱
  已出貨 1,050（4 客戶）＋ 庫存 130 ＋ 報廢 12 ＋ 留樣 6 = 1,198 箱 → 99.8% ✅
斷點：成品批 <批號3> 有 1 桶重工品來源批號未記錄
改善：重工登記表加「來源批號」必填欄（負責：生管，期限：<日期>）
本紀錄為 AI 整理草稿；回收與通報決定由業者負責人 / HACCP 小組簽核。
審查：＿＿＿＿　日期：＿＿＿＿
```

## 真實事件時（不是演練）

1. 立即通知負責人與 HACCP 小組 — **AI 不決定是否回收**
2. 先隔離、標示庫存品，暫停出貨受影響批
3. 依本 skill 步驟 2–4 算出影響範圍，交人判定
4. 台灣法規：業者發現產品有危害衛生安全之虞時，須主動停止販售、辦理回收並通報地方主管機關（食安法相關條文、回收分級與時限需驗證）

---

## Anti-patterns

- ❌ 只演練「向後追」— 客戶清單才是回收真正花時間的地方
- ❌ 每次都由同一個熟手執行 — 要測的是系統，不是某個人的記憶
- ❌ 演練完沒有改善事項 — 稽核會看上一次的改善有沒有落實
- ❌ 質量平衡差 10% 寫「合理損耗」— 要找出去哪了
