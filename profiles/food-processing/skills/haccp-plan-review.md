# HACCP 計畫檢視 Skill

> ⚠️ **Alpha**：步驟與決策樹依 Codex《食品衛生一般原則》（CXC 1-1969，現行修訂版次需驗證）與 ISO 22000:2018 的公開架構整理。**產出只是給 HACCP 管制小組的檢視清單，不是核准。**

由 **haccp-coordinator** 主導。

---

## 12 步驟 checklist

前 5 步是準備，第 6–12 步對應 7 大原則。

| 步驟 | 內容                       | 檢查重點                                                       |
| ---- | -------------------------- | -------------------------------------------------------------- |
| 1    | 組成 HACCP 小組            | 跨部門（品保、生產、工務、採購）；成員訓練紀錄；負責人明確     |
| 2    | 產品描述                   | 成分、pH / 水活性、包裝、保存條件、有效期限、過敏原            |
| 3    | 確認預定用途與消費族群     | 是否給嬰幼兒、長者、免疫低下者；是否需再加熱                   |
| 4    | 製作流程圖                 | 含原料進廠、重工、回收料、廢棄、副產品                         |
| 5    | 現場確認流程圖             | 小組有沒有**實際走線**並簽名日期                               |
| 6    | 原則 1：危害分析           | 生物 / 化學（含過敏原）/ 物理危害逐步列出；評估嚴重性與可能性 |
| 7    | 原則 2：決定 CCP           | 用下方決策樹；每個判定有理由                                   |
| 8    | 原則 3：建立管制界限       | 可量測；有確效依據（法規、文獻、試驗）                         |
| 9    | 原則 4：建立監控程序       | 誰、量什麼、怎麼量、多久一次、記在哪                           |
| 10   | 原則 5：建立矯正措施       | 偏差時：恢復管制 + 受影響產品處置 + 誰有權判定                 |
| 11   | 原則 6：建立確認（驗證）程序 | 紀錄覆核、儀器校正、內部稽核、年度再確認                       |
| 12   | 原則 7：文件與紀錄         | 版本管理、保存期限、可追溯到批號                               |

## CCP 判定樹（經典 Codex 版，逐一危害、逐一步驟問）

```
Q1  此步驟（或之後步驟）有沒有針對此危害的管制措施？
     ├─ 否 → 此步驟需要管制才能確保安全嗎？
     │        ├─ 是 → 修改步驟 / 製程 / 產品，再回 Q1
     │        └─ 否 → 非 CCP
     └─ 是 → Q2
Q2  此步驟是否「專門設計」來消除危害或降到可接受程度？
     ├─ 是 → ★ CCP
     └─ 否 → Q3
Q3  污染是否可能在此發生，或增加到不可接受的程度？
     ├─ 否 → 非 CCP
     └─ 是 → Q4
Q4  後續步驟能否消除危害或降到可接受程度？
     ├─ 是 → 非 CCP（由後續步驟管制）
     └─ 否 → ★ CCP
```

> 2020 年後 Codex 修訂版把決策樹改為「工具之一」並強調先判斷危害是否「顯著」；ISO 22000 另有 CCP / OPRP 分類（見 [`haccp-iso22000-basics`](../know-how/haccp-iso22000-basics.md)）。**你的驗證機構採用哪一版，需驗證。**

## Process（agent 怎麼跑這個 skill）

1. 請使用者提供：產品描述、流程圖、危害分析表、HACCP 計畫表（CCP / 界限 / 監控 / 矯正 / 確認 / 紀錄）
2. 依 12 步驟逐項標 ✅ 齊全 / ⚠️ 不完整 / ❌ 缺
3. 對每個 CCP 跑一次決策樹，若判定與文件不同 → 列為「需小組討論」，**不改文件**
4. 對每個管制界限問「依據是什麼？」— 沒寫依據的列出
5. 對照 [`food-defects-and-ccp-examples`](../know-how/food-defects-and-ccp-examples.md) 檢查有沒有常見危害被漏掉（過敏原、金屬、冷卻）
6. 輸出檢視報告（格式如下），最後一行固定是簽核欄

```
HACCP 計畫檢視草稿 — <產品名> <版次>
齊全：步驟 1,2,4,9,12
不完整：步驟 5（流程圖現場確認無簽名日期）
         步驟 8（CCP-2 冷卻界限「2 小時內降到 7°C」未寫依據）
缺：步驟 6 未評估芝麻交叉污染（同線生產芝麻醬）
需小組討論：金屬檢測（文件列 OPRP，依決策樹 Q2 可能是 CCP）
本報告為 AI 草稿，不構成 HACCP 計畫核准。
HACCP 小組審查：＿＿＿＿　日期：＿＿＿＿
```

## Anti-patterns

- ❌ CCP 越多越好 — CCP 太多代表 PRP 沒做好，現場也監控不來
- ❌ 照抄別廠或教科書的 HACCP 計畫 — 流程、設備、產品不同，危害就不同
- ❌ 只有危害分析結論沒有理由 — 稽核會問「為什麼這步不是 CCP」
- ❌ 管制界限寫「適當溫度」「足夠時間」— 必須是可量測的數值
- ❌ 換配方 / 換設備 / 換供應商後沒有重新做危害分析
