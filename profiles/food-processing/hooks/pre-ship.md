# pre-ship Hook（食品版）

> ⚠️ **Alpha**：此 hook 取代 core 的 [`pre-ship`](../../../core/hooks/pre-ship.md)，在一般出貨檢查之外加上食品批次放行要件。**AI 只檢查文件是否齊全，不做放行判定；放行簽核由品保 / 具權責的人執行。**

食品一旦出廠，出問題就是回收。這關檢查「放行要件齊不齊」，不是「產品安不安全」。

---

## 檢查清單

### A. 食品批次放行要件

- [ ] 該批所有 **CCP 監控紀錄**完整（無空格），且已由監控者以外的人覆核簽名
- [ ] 該批若有 **CCP 偏差**：偏差紀錄、產品處置、HACCP 小組簽核**都已存在** — 缺任一項就不得出貨
- [ ] **成品檢驗報告 / CoA**（依產品規格：微生物、理化、感官等）已出具且合格；需委外檢驗者報告已回
- [ ] **批號、製造日期、有效日期**：標籤 = 生產紀錄 = 出貨單，三者一致
- [ ] **過敏原標示**與該批實際配方一致（含配方變更後的包材版次）
- [ ] **冷藏 / 冷凍品**：成品庫溫度紀錄完整無異常；出貨車輛預冷與溫度紀錄安排
- [ ] **留樣**已依規定保留並登記批號

### B. 一般出貨要件（沿用 core）

- [ ] OQC 報告已產出且簽核
- [ ] 包裝 / 標籤符合客戶規範：品名、批號、數量、客戶 PO
- [ ] 隨貨文件齊全：Packing List、商業發票、CoA（依客戶要求）、出口文件（產地證明、衛生證明等，依進口國要求）
- [ ] 收貨人 / 地址 / 電話與訂單一致；貨運與到貨日確認

> 非食品料號（多 profile 安裝時）只需跑 B 段。

---

## 失敗處理

任一項缺：

```
🛑 出貨暫停 — 缺少：
- 批號 <批號> 殺菌 CCP 紀錄 14:00–16:00 無覆核簽名
- 過敏原標示：配方含芝麻，標籤版次 V3 未標示

這是文件檢查結果，不是產品安全判定。
補齊並由品保簽核放行後，重新觸發 pre-ship。
```

---

## 通過動作

- 輸出「放行要件齊全」摘要，**等待品保簽核放行**（AI 不代簽）
- 簽核後：寫入出貨紀錄（含成品批號）、通知客戶、更新訂單狀態
- 出貨單批號與數量同步給 [`traceability-officer`](../agents/traceability-officer.md) 的追溯紀錄
