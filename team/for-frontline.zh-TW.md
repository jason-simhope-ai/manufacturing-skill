# 分身與我（給前線同仁的一頁說明）

> 給每天在現場、在電話旁、在檢驗台做事的同仁。看完約 3 分鐘。給主管與 IT 的版本在 [README](README.zh-TW.md)。

## 這是誰的分身

分身是某個**職位**的副駕（住在公司聊天頻道裡的 AI 助手），例如「品保部主管分身」。它幫那個職位多看相似案與反例，回答前面都標著【某某分身】。它不是你的替身，也不是你的主管。

## 它不是什麼

- **不是指示。**每則回覆都寫著「這是參考，不是指示」。
- 不替任何人做決定；遇到要判斷的事，它列出選項交還給人（🧭 需要你判斷）。
- 不寫入任何系統、不對外發送、不評比個人，也不記得昨天的對話。
- 會不會取代你？**以公司簽署的「AI 賦能原則」（公司寫下的書面承諾，例如分身不取代人、紀錄不拿來評比）為準**；簽署日期應該貼在分身頻道的說明裡。沒有簽，就不該導入。

## 分身的每項能力分三類

| 類別 | 意思 | 對你的影響 |
| ---- | ---- | ---------- |
| 強化既有優勢（`strengthen`） | 你仍親手判斷，分身補資料與反例 | 你的判斷不變，多一份對照 |
| 創造新能力（`create`） | 以前沒人做的事，例如每日趨勢提醒 | 沒有人的工作被拿走 |
| 外包既有工作（`outsource`） | 今天有人在做、上線後那個人不再做 | **預設休眠**（不啟用）；要啟用，做這件事的人本人要先看過並簽字，公司原則也要允許 |

## 你可以做什麼

| 說這句（先打 @ 加分身名字叫它） | 會發生什麼 |
| ------------------- | ---------- |
| 「我先說」 | 你先寫下自己的判斷，分身再拿相似案與反例對照。學習頻道預設就是這樣；想直接看，說「這次直接給」 |
| 「我不同意」或「分身錯了」 | 分身只回一句「收到」，不再給新答案。系統只記「哪個頻道、哪項能力被不同意」一筆，**不記是誰**（聊天平台上仍看得到是誰發的訊息） |
| 「緊急」 | 在「不用分身日」也照常回答。不用分身日由頻道設定（每月某幾天），那天分身只回「今天請自己判斷」 |
| 「我親手做了」 | 自報親手練習一次，只計數，不記是誰 |

不想用，就不用。不會有人因為沒用分身而被追責。

在學習頻道（例：品保學習頻道 `qa-learn`）裡，分身只給相似案與反例，不給嚴重度或合格與否的建議；你寫的判斷不會出現在別人的對話裡。

## 錯了誰負責

分身的答案是參考。**沒有人會因為「分身這樣說」而被追責，也沒有人會因為沒用分身而被追責；簽字採用結論的人負責結論。**

分身答錯了：在那則訊息底下的討論串（thread）回「我不同意」，或在每週檢討會（review）提出。紀錄只到工單與能力，不寫人名。

## 你的名字出現在「今天誰在做」那一行

每項能力都寫著「今天誰在做」（設定檔欄位 `today`）和「上線後人還親手做什麼」（欄位 `humanStillDoes`）。如果寫的是你的職位，上線前應該有人拿那兩行給你看，你同意了才算數（記在欄位 `doerAckedOn`）。沒有人問過你，或寫得不對，你可以要求暫停那個職位的分身。

## 你的資料

- 系統留的稽核紀錄不存訊息文字，只存「指紋」（雜湊，無法還原成原文）與次數。
- 主管不得用你的使用次數或修改次數評價你；報表只到公司層級或 5 人以上的群組。
- 客戶名、人名、金額、圖號不要貼進分身頻道；拿不準就先問主管。
