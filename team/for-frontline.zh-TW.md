# 分身與我（給前線同仁的一頁說明）

> 👥 **給誰看**：業務助理、品保檢驗員、生管，以及每天在現場、在電話旁、在檢驗台做事的同仁。看完約 5 分鐘，不用懂電腦。
> 🧪 **實驗版**：公司先在測試用的聊天室、用虛構或已去識別的資料試。給主管與 IT 的版本在 [README](README.zh-TW.md)；一張圖的版本在 [05 分身團隊](../docs/explainers/05-分身團隊-一張圖看懂.html)，一步一步的示範在 [點擊式示範](../docs/demo/team-demo.html)。

## 🤖 分身是誰的

分身是某個**職位**的副駕（住在公司聊天頻道裡的 AI 助手），例如「品保部主管分身」。它幫那個職位多看相似案與反例，回答前面都標著【某某分身】。

它**不是你的替身，也不是你的主管**。

## 🚫 它不是什麼

- **不是指示。** 每則回覆都寫著「這是參考，不是指示」。
- **不替任何人做決定。** 遇到要判斷的事，它列出選項交還給人（🧭 需要你判斷）。
- **不動手。** 不寫入任何系統、不對外發送、不評比個人。不保留長期記憶：只帶入這個頻道最近 10 則訊息（問與答各算一則，含別人的），重新啟動就清空。

## 🗂️ 分身的工作分三種

| 類別 | 意思 | 對你的影響 |
| ---- | ---- | ---------- |
| 💪 強化既有優勢 | 你仍親手判斷，分身補資料與反例。例：品保主管先判不良的嚴重度，分身再拿相似案來對照 | 你的判斷不變，多一份對照 |
| ✨ 創造新能力 | 以前沒人做的事。例：每天看 SPC 數字的走勢，變壞先提醒（檢驗員照常填 SPC 表） | 沒有人的工作被拿走 |
| 📦 外包既有工作（預設關閉） | 今天有人在做，上線後那個人不再做。例：品保工程師手動排 8D 報告的版面 | **預設休眠**（不啟用）。要啟用，做這件事的人本人要先看過並簽字，公司原則也要允許 |

## 🙋 我可以做什麼

先打 @ 加分身名字叫它，再說這幾句：

| 你說 | 會發生什麼 |
| ---- | ---------- |
| 「我先說」 | 你先寫下自己的判斷，分身再拿相似案與反例對照。學習頻道預設就是這樣；想直接看，說「這次直接給」 |
| 「我不同意」或「分身錯了」 | 分身只回一句「收到」，不再給新答案。系統只記「哪個頻道、哪項能力被不同意」一筆，**不記是誰**（聊天平台上仍看得到是誰發的訊息） |
| 不用分身日 | 頻道可以設每月某幾天不用分身，那天分身只回「今天請自己判斷」。真的急，訊息裡寫「緊急」，就照常回答 |
| 「我親手做了」 | 自報親手練習一次，只計數，不記是誰 |

**不想用，就不用。** 不會有人因為沒用分身而被追責。

**🎓 在學習頻道**（例：品保學習頻道 `qa-learn`）：回覆標著「學習模式」。分身只給相似案與反例，不給嚴重度或合格與否的建議；預設你先說。你寫的判斷不會出現在別人的對話裡。

## ⚖️ 答錯了，誰負責

分身的答案是參考。**沒有人會因為「分身這樣說」而被追責，也沒有人會因為沒用分身而被追責；簽字採用結論的人負責結論。**

## 📊 會不會用來考核我

- **不會。** 主管不得用你的使用次數或修改次數評價你；報表只到公司層級或 5 人以上的群組。
- 系統留的稽核紀錄不存訊息文字，只存「指紋」（雜湊，無法還原成原文）與次數。
- 「我不同意」「我親手做了」只算次數，不記是誰。

## ✋ 我可以拒絕嗎

- **可以不用。** 見上面「不想用，就不用」。
- **寫到你的工作，要先問你。** 每項能力都寫著「今天誰在做」和「上線後人還親手做什麼」。如果寫的是你的職位，上線前應該有人拿那兩行給你看，你同意了才算數。沒有人問過你，或寫得不對，你可以要求暫停那個職位的分身。
- **開分身前，主管要先回答 9 個問題**（「需要分身嗎？」紙本問卷）。其中兩題問的是你：「今天實際做這件事的人訪談過了嗎？」「那個人看過『今天誰在做』那一行，並同意寫得對嗎？」答「否」就先不開。
- **會不會取代你？** **以公司簽署的「AI 賦能原則」（公司寫下的書面承諾，例如分身不取代人、紀錄不拿來評比）為準**；簽署日期應該貼在分身頻道的說明裡。沒有簽，就不該導入。

## 📣 怎麼反映問題

- **分身答錯了**：在那則訊息底下的討論串（thread）@ 分身回「我不同意」，或在每週檢討會（review）提出。紀錄只到工單與能力，不寫人名。
- **你的工作寫錯了、沒人問過你**：跟主管說，要求暫停那個職位的分身。
- **有人拿分身紀錄評比個人，或有不該貼的東西被貼進頻道**：照公司簽的原則裡「違反時」那一條，向受理人報告，可以匿名；報告的人不受不利對待。
- **客戶名、人名、金額、圖號不要貼進分身頻道**；拿不準就先問主管。

- **學習模式**：roster `channels[].learners` 列的職位，回覆上限 `suggest`、標「學習模式」，只給相似案與反例（這是 prompt 規則，不是程式保證）；他們的對話不進頻道窗。`predictFirstDefault: true` 讓學習者預設「我先說」，「這次直接給」跳過一次。「我先說」只對標了 `predictFirstEligible` 的能力有效。
- **不用分身日**：roster `channels[].twinFreeDays`（每月第幾天，依 `org.timezone`），那天排程貼文也停；只是「每月幾號」的清單，沒有假日判斷。
- **稽核計數**：「我不同意」／「分身錯了」記 `human_override`，「我親手做了」記 `practice_checkin`，不用分身日記 `twin_free_day`；都只記頻道與分身（前兩種另記能力），不記使用者。`teamctl audit-verify` 依頻道／能力加總印出，不按人拆。
