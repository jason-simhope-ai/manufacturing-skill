# 「需要分身嗎？」閘門

> 名詞對照：**分身**＝某個職位的 AI 副駕（聊天室裡的 AI 助手），不是人的替身。**roster**＝名冊檔，記錄有哪些部門、職位、哪些職位有分身。**T3**＝受管制或客戶要求保密的專案資料。**閘門**＝開分身之前要先過的一份檢查問卷。

流程修正能解決的，就不開分身。由 `/team gate <position>`（在 Claude Code 裡輸入的指令）逐題引導 G1–G6、G8、G9；**G7 不在對話中問**，由人在下方名冊（roster）片段的註解裡自己填 yes／no。全部通過才可填 `result: twin`。每季複審一次。不用電腦的人，請用文末的「紙本版」。

## 問卷

| # | 問題 | 不通過 → |
| - | ---- | -------- |
| G1 | 這個痛點每週耗幾小時？（要說得出數字；只用來決定值不值得開，不是成效指標） | `defer`（先不開） |
| G2 | 根因是表單、權責、流程斷點，或資料尚未數位化嗎？ | `process-fix`（先修流程） |
| G3 | 偶爾用一次既有的 `/command`（現成的指令，例如 `/inspect`、`/quote`）就能解決嗎？ | `use-command`（用既有指令） |
| G4 | 在職者願意每週花 15 分鐘 review（檢討分身的回答）嗎？ | `defer`（先不開） |
| G5 | 需要的資料都可讀（已數位化、可匯出）嗎？ | `defer`（先不開） |
| G6 | 實際在做事的人（常是下屬）已訪談，`today`（「今天誰在做」那一欄）已填嗎？ | `defer`（先不開） |
| G8 | 今天實際做這件事的人看過分身檔的 `today`／`humanStillDoes`，並同意寫得對嗎？（`affectedRoles`＝受影響的人；不是本職位的，填 `doerAckedOn`，即他同意的日期） | `defer`（先不開） |
| G9 | 分身停一週，你還做得出來嗎？做不出來就先不開 | `defer`（先不開） |
| G7 | 涉及 T3（受管制或客戶要求保密的專案資料）嗎？**紙上自行確認，不要輸入任何聊天或 AI 對話**（答「有，某某客戶的保密案」本身就洩漏）。在名冊片段的 G7 註解填 yes／no | yes → 試驗版（alpha）不開，`result` 只能是 `defer`，見 `team/policies/restricted.md` |

G2、G3 答「是」就走對應的出口，不再往下問。G7 是人自己填的 yes／no，工具與分身都不問、不記。

職位是空缺（`incumbent: VACANT`，即目前沒有人在這個職位上）？先寫下**為什麼空著**。分身不是補人的方法：空缺職位的分身只到 `observe`，啟用還要升級梯上的人簽 `vacancyApprovedBy`／`vacancyApprovedOn`（否則 `E064`）。

## 結果與去向

| `result` | 意義 |
| -------- | ---- |
| `twin` | 可以在 roster 設 `enabled: true` |
| `process-fix` | 先修流程；修完再問一次 |
| `use-command` | 用既有指令，不開分身 |
| `defer` | 條件未備，列出缺什麼、下季再評 |
| `retire` | 複審後判定停用 |

## 輸出：貼進 roster 的片段

```yaml
# G7 涉及 T3（受管制或客戶要求保密的專案）？ 請你自己在這裡填 yes / no（不要在聊天回答）：____    yes → result 改 defer，alpha 不開
needsTwinGate:
  result: twin
  rationale: 一句話寫出痛點、已訪談誰、資料在哪
  reviewedOn: "YYYY-MM-DD"   # 超過 120 天未複審會出現 W004
```

## 季複審清單

- 週 review 出席率與「🧭 修改率」（> 0 是健康的）。
- 「我不同意」次數：`teamctl audit-verify`（檢查稽核紀錄有沒有被改動的指令）印出的 `human_override` 計數（只到頻道與能力，不記是誰）。0 不代表分身都對，可能是大家不敢說；次數多的能力先檢討。「我親手做了」（`practice_checkin`，自報）與不用分身日（`twin_free_day`）的計數一起看。
- 分類分布：有沒有把 outsource（外包既有工作）標成強化？有爭議一律判 outsource。做事的人（`affectedRoles`）換了、或分類改了，`doerAckedOn` 要重簽。
- 已喚醒的 outsource（外包既有工作）：teach-back（在職者定期用自己的話講回那件事怎麼做）與人工練習有沒有做？`reviewBy` 是否到期？
- 這個分身還需要嗎？不需要就判 `retire`。

技能保留紀錄與使用指標只用於改善分身，**不作為人力或績效依據**。

## 紙本版（9 題，給不用電腦的人；印出來填）

編號與上方問卷相同。每題圈「是」或「否」：**「是」就往下一題；「否」就停，照括號做**，不用再往下。

- G1 這件事每週花多少小時，寫得出數字嗎（只用來決定值不值得開，不是成效指標）？　是／否（否：先不開，先記一週的時間）
- G2 表單、權責、流程都順，資料也已經在電腦裡，問題不是出在這些地方嗎？　是／否（否：先修流程，修完再問一次）
- G3 偶爾用一次現有的指令（例如報價、檢驗）不夠，需要每天都有副駕嗎？　是／否（否：用現有的，不開分身）
- G4 主管願意每週花 15 分鐘，看分身的回答和大家的「我不同意」嗎？　是／否（否：先不開）
- G5 需要的資料讀得到嗎（已經在電腦裡、能匯出、能先拿掉客戶名與人名）？　是／否（否：先不開）
- G6 今天實際做這件事的人（常是下屬）已經訪談過了嗎？　是／否（否：先不開，先去問）
- G8 那個人看過「今天誰在做」那一行，並同意寫得對嗎？　是／否（否：先不開）
- G9 分身停一週，你還做得出來嗎？　是／否（否：先不開）
- G7 這件事完全不牽涉受管制或客戶要求保密的專案（例如航太、醫療器材、保密協議專案、出口管制品項）嗎？**只在紙上圈，不要打進任何聊天或 AI**　是／否（否：先不開，照公司處理受管制專案的程序）

9 題都圈「是」：**可以試**。結果只會是四種之一：先修流程／用現有指令／先不開／可以試。
